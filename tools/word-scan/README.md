# 出したくない語スキャン

Scans a git repository's commits to be pushed and its files for words you listed as not to publish, using only Python 3 and git.

公開するリポジトリに push する前に、出したくない語（名前・メールアドレス・ホームフォルダ名など）が入っていないかを検査します。1件でも当たれば終了コード 1 で止まります。直すのは手です。

## 入れるもの
- 検査するリポジトリのフォルダ（`--repo`）
- 検査語のファイル（`--words`・書き方は下の「検査語のファイルの書き方」）
- 任意: push する差分の範囲（`--range`・既定は `origin/main..HEAD`）

## 見るもの
- push する差分: コミットごとに、見出しと本文・著者とコミッターの名前とアドレス・足した行・新しいファイルの名前・名前を変えた先
- 今の中身（`--tree` のとき）: `git ls-files` の全ファイルのうち、UTF-8 で読めるものの全部の行
- 見ないもの: 差分の前後に写る前からある行・消した行・埋め込み画像のデータ（`data:image` で始まる文字列）・UTF-8 で読めないファイル

## 出るもの
1. 表: コミットごとと今の中身ごとに「検査語／ヒット数／実物（最大5件・前後30字）」。メールアドレスとホームフォルダ名は値を出さず「（値は伏せる）」
2. 最後の1行: 「検査語 N語（ファイル名）／ヒット合計 N」
3. 終了コード: 1件でも当たれば 1、無ければ 0

## 手順（3つ）
1. `words_example.txt` を写して、自分の出したくない語に書き換える（例: `my_words.txt`）。このファイルは、公開するリポジトリの外に置く
2. push の前に走らせる
   `python3 word_scan.py --repo ~/projects/my-tools --words ~/private/my_words.txt --tree`
3. 当たったら、表の実物を見て直す。公開してよいものに当たったときは、下の「逃がし方」で外す。もう一度走らせて、ヒット合計 0 を確かめてから push する

## 検査語のファイルの書き方

1行1つ。`#` で始まる行と空行は飛ばします。

| 書き方 | 意味 |
|---|---|
| `語` | そのまま部分一致（大文字と小文字を区別する） |
| `i:語` | 大文字と小文字を区別しない部分一致 |
| `re:式` | 正規表現（Python の re） |
| `@EMAIL` | メールアドレスの形。`allow-email` にあるもの以外を数える。値は伏せる |
| `@HOME` | 実行した PC のホームフォルダ名。値は伏せる |
| `allow-email: アドレス` | `@EMAIL` の検査から外すアドレス |
| `allow-line: ファイル名の一部 \| 行に含まれる文字列 \| 理由` | ファイル名と行の両方が合う行だけ、全部の検査語から外す |

## 逃がし方（公開してよいものに当たったとき）

| 逃がし方 | 使う場面 | 書き方 |
|---|---|---|
| メールの許可 | 公開している問い合わせ先や、コミットの著者に使う公開用のアドレス | 検査語のファイルに `allow-email: info@example.com` |
| 行の許可 | 改名の経緯など、わざと残す行 | 検査語のファイルに `allow-line: docs/history.md \| 旧名「もぐら町」 \| 改名の経緯として、わざと残す行` |
| 既知の件数 | 前から公開していて、すぐには直せない語 | 走らせるときに `--known もぐら町`。その語は件数だけ出し、合計と終了コードに数えない。直したら外す |

## AI に守らせる決まりの1行

AI に公開物を書かせたり push させたりするときは、AI への指示（CLAUDE.md など）に次の1行を入れておきます。

```
公開するリポジトリに push する前に、word_scan.py で push する差分とリポジトリの今の中身（--tree）を検査し、ヒット0件を確かめる。当たったら push せずに直し、もう一度検査する。
```

## 用意するもの
- Python 3（標準ライブラリだけ）と git
- 検査語のファイル（`words_example.txt` を写して作る）

## できないこと
- 一覧に無い語は見つけない。検査語のファイルに書いた語と形だけを見る
- 画像の中の文字は見ない。画像や PDF など、UTF-8 で読めないファイルは飛ばす
- ホームフォルダ名は、実行した PC のものだけを見る。ほかの PC のホームフォルダ名は、検査語のファイルに書かないと見つけない
- 確かめた環境は macOS（Python 3.9・git 2.54）だけ。Windows と Linux では確かめていない
- 当たった箇所は直さない。push を自動で止める設定も入っていない（手で走らせる）

## 内部版から外したもの

ぼくが自分のリポジトリで使っている内部版から、次を外しました。

- 内部版の検査語のファイル（例は架空の語だけで作り直した）
- 内部の文書を置くフォルダだけ、検査語を減らして見る扱い（コードごと外した）
- 内部版で同じ検査語を読む、ほかの仕組みとのつなぎ
- 使い方の例とコメントにあった、作業の呼び名・日付・実在のコミットの範囲
