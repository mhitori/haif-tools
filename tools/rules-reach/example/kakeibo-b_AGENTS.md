# AGENTS.md

## このプロジェクト

- これは、家計簿の CSV を月ごとに集計する Python のスクリプトです
- 返事は日本語で書く
- 集計の表は1行を80文字までにし、色で区別しない
- 分からないことがあれば推測で進めず、先に質問する

## コードを書くとき

- Python は 3.12 を使う
- 外部のライブラリを足さない
- 関数には型ヒントを付ける
- 金額は整数（円）で扱う
- 変数名は英語にし、コメントは日本語で書く
- 1つの関数は50行までにする
- 日付は datetime.date で扱い、文字列のまま比べない
- 消費税の計算は tax.py の関数だけを使い、ほかの場所に税率を書かない
- print でのデバッグは、コミットの前に消す
- 例外は握りつぶさず、どの行の CSV で失敗したかをメッセージに書く

## 検査

- コードを変えたら pytest を走らせる
- テストが落ちたままコミットしない
- テストを足すときは tests/ に置き、ファイル名は test_ で始める
- 金額の計算を変えたら、端数の切り捨ての境目を確かめるテストを足し、結果を報告に書く
- 型の検査は mypy で行う

## ファイル

- data/ の CSV を書き換えない
- 出力は out/ に書く
- 個人の口座番号が入ったファイルは、リポジトリに入れない
- 設定は config.toml にまとめ、コードの中に値を直接書かない
- out/ の中身はコミットしない
- 新しいフォルダを作るときは、先に理由を伝え、了承をもらってから作る

## 記録

- コミットメッセージは日本語で書く
- 1つのコミットには1つの変更だけを入れる
- 変更したら CHANGELOG.md に1行足す
- 報告では、やったことと、やっていないことを分けて書く

## 依存と版

- requirements.txt を手で書き換えない
- Python の版を上げる話は自分で決めず、理由と影響を書いて相談する

## 文書

- README.md の使い方の節は、コマンドを変えたら同じコミットで直す
- 文書は「です・ます」で書く

## してはいけないこと

- data/ のファイルを消さない
- git push はしない
- 鍵やパスワードを、コード・ログ・報告のどこにも書かない
- ネットにつながる処理を足さない
- 頼まれていないファイルの整形（空白や並び順の直し）をしない

## 困ったとき

- 同じエラーで2回直しても通らなければ、3回目を試す前に止め、エラーの全文と試したことを報告する
- 決まり同士が食い違って見えるときは、どちらにも従わず、食い違う箇所を書いて聞く
